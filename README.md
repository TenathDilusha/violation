# Detecting Code of Conduct Violations in Sri Lankan News with LLMs

This project checks whether news articles (Sinhala and English) break the Editors' Guild of Sri Lanka **Code of Professional Practice**, and answers three questions for each article:

| Question                | Output                                       |
| ----------------------- | -------------------------------------------- |
| Does it break the code? | Violation / no violation                     |
| Which rules?            | Rule ids, e.g. `2.2.a`, `6.1.b`              |
| Which words?            | The exact passages that break each rule      |

Three models were tested: **gpt-4.1**, **Gemini 3.5 Flash** and **SinLlama 8B**. Each was asked in **9 ways** (3 tasks × 3 prompt styles). The best approaches are confidence scores built from gpt-4.1's answers. They catch about **90% of violations at 86–91% precision** (F2 90 on 106 articles).

The slides are in [`presentation/violations_presentation.pdf`](presentation/violations_presentation.pdf), and longer notes for each slide are in [`presentation/slide_notes.md`](presentation/slide_notes.md).

## How to run

### 1. Build the dataset

```bash
.venv/bin/python extract.py           # source DB → data/*.csv
.venv/bin/python import_external.py   # data/*.xlsx → data/external_violations.csv
.venv/bin/python load_to_db.py        # data/*.csv → violations schema
```

### 2. Run the models

Every runner takes `--prompt <module in prompts/>` and writes to two places:

- `<task>/outputs/<experiment>_<provider>_<model>_<timestamp>.jsonl`;
- the matching `violations.*_predictions` table.

Articles that already have an answer are skipped, so an interrupted run can be resumed.

```bash
# One task, one prompt
.venv/bin/python llm/run_openai.py --prompt few_shot --negatives 30
.venv/bin/python rule_detection/run_gemini.py --prompt zero_shot --negatives 30
.venv/bin/python span_detection/run_openai.py --prompt per_rule --negatives 30

# All 9 ways for one provider
./run_all.sh openai --workers 6
./run_all.sh gemini --workers 6
./run_all.sh sinllama                 # uses anish_project's venv, Sinhala only

# Repeats 2 and 3 (stored as <prompt>.r2, <prompt>.r3)
./run_all.sh openai --repeat 2
./run_all.sh openai --repeat 3

# Sinhala code of conduct on Sinhala articles (stored as <prompt>_si_code)
./run_all.sh openai --code-lang si --lang si

# Rule detection prompts revised from zero-shot's mistakes
.venv/bin/python rule_detection/run_openai.py --prompt zero_shot_v3 --negatives 30

# Two-step pipelines (gpt-4.1)
.venv/bin/python two_step/run.py --negatives 30

# SinLlama directly
PYTHONPATH=~/anish_project/.python_pkgs ~/anish_project/venv/bin/python llm/run_sinllama.py --prompt per_rule --negatives 30

# Fill in every method for newly added articles
./run_missing.sh openai --workers 3
```

**Common options** (all runners):

| Option              | Meaning                                                                                       |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `--prompt NAME`     | Prompt module: `zero_shot`, `few_shot`, `per_rule` (rule detection also `zero_shot_v2`, `zero_shot_v3`) |
| `--negatives N`     | Add the first N clean articles **per language** (all results use `--negatives 30`)           |
| `--lang en\|si`     | Only articles in that language                                                                |
| `--repeat N`        | Store as repeat N (`<prompt>.rN`); the reported numbers are the mean of repeats 1–3           |
| `--code-lang si`    | Put the Sinhala code of conduct in the prompt (needs `--lang si`)                             |
| `--model NAME`      | Override the model (defaults: `gpt-4.1`, `gemini-3.5-flash`, `sinllama-8b`)                   |
| `--limit N`         | Only the first N articles                                                                      |
| `--force`           | Re-run articles that already have an answer                                                    |
| `--workers N`       | Parallel API calls (default 4)                                                                 |

### 3. View the results

```bash
.venv/bin/python app.py               # → http://127.0.0.1:5002
```

| Page            | What it shows                                                                                                   |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| `/overview`     | The whole project for non-specialists, step by step. Covers every approach tried, the top 4, and one leaderboard ranked by F2 |
| `/compare`      | Every model × task × prompt scored on the same articles, per language: a metric grid, all metrics, and per-article answers |
| `/best-model`   | The #1 approach with 95% intervals, per language and per source of violations                                    |
| `/article/<id>` | One article with every run's answer, named rules and highlighted evidence                                        |

All numbers are computed from the database when a page loads.

## Method

### Code of conduct

`code_of_conduct/code_of_conduct.json` holds 17 rules in 5 groups. Each rule records its obligation, the conditions for a breach, its exceptions (public interest, consent, …) and evidence cues.

| Group                | Rules                                                                                                    |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| Accuracy             | 2.2.a unsourced claims · 2.2.b non-credible source · 2.2.c irrelevant source · 2.5 mixing comment and fact |
| Harm and sensitivity | 6.1.a sensational treatment · 6.1.b murder-method detail · 6.1.c crime-method detail · 6.5 suicide-method detail |
| Crime identification | 6.2.i sex-crime victims · 6.2.ii young accused · 6.2.iii relatives of the accused                        |
| Discrimination       | 6.3 communal discord · 6.4.i pejorative references · 6.4.ii irrelevant identity details                  |
| Privacy              | 7.1 private and family life · 7.4 children · 7.5 people in hospitals and institutions                    |

- **Excluded:** rules that need fact-checking, photos or newsroom knowledge (2.1, 2.3, 2.4, 3, 4, 5, 7.2, 7.3, 8 and 9).
- **Labels:** two only, `VIOLATION` and `NO_VIOLATION`. Missing information, such as unknown consent, is never treated as evidence.

### Dataset (106 articles)

|                    | Sinhala | English | Total   |
| ------------------ | ------- | ------- | ------- |
| Violations         | 15      | 32      | **47**  |
| Clean articles     | 29      | 30      | **59**  |
| **Total**          | **44**  | **62**  | **106** |

- **Violations:**
  - 19 were reviewed on the platform (`REVIEWED_VIOLATION`, `DECIDED_CRITICAL`, `DECIDED_NON_CRITICAL`);
  - 28 come from the external spreadsheets (`EXTERNAL_VIOLATION`, ids `ext-…`).
- **Clean articles:**
  - Sinhala ones are `REVIEWED_NON_VIOLATION`;
  - no English article has been reviewed as clean, so the English ones are random unreviewed articles, labelled `ASSUMED_NON_VIOLATION`.
- **Correct rules and highlights** are annotated at three levels: violation or not, which rule, and which words. They come from `violations.manual_annotations`, or else from `span_detection/reviewed_suggestions.json`.
- **Few-shot examples:** the 6 example articles (3 per language) are left out of every score.

### The 9 ways (3 tasks × 3 prompts)

| Task                       | The model returns            | Counts as a violation when                 |
| -------------------------- | ---------------------------- | ------------------------------------------ |
| Violated? (`llm/`)         | `YES` / `NO`                 | it says YES                                |
| Rule detection             | broken rule ids + evidence   | it names at least one rule                 |
| Highlights                 | rule id + exact excerpt      | an excerpt is found in the article         |

| Prompt    | What the prompt holds                                                     |
| --------- | ------------------------------------------------------------------------- |
| Zero-shot | The code of conduct and the article                                       |
| Few-shot  | The same, plus 3 worked examples in the article's language                |
| Per-rule  | A verdict and evidence for each of the 17 rules, one by one               |

Other approaches built on top of these:

- **Repeats:** every gpt-4.1 and SinLlama run was done 3 times. gpt-4.1 varies between runs even at temperature 0.
- **Sinhala code of conduct** (`--code-lang si`): the same prompts, with the code in Sinhala.
- **Revised rule detection prompts** (`zero_shot_v2`, `zero_shot_v3`): guidance written after reading every zero-shot mistake.
- **Two-step pipelines** (`two_step/`): two variants.
  - rules first, then the words for each rule;
  - words first, then the rule for each passage.
- **Voting:** an article is a violation when at least k of the 9 ways flag it.
- **Confidence scores** (`evaluation/confidence.py`, `evaluation/scores.py`): 37 scores built from the stored gpt-4.1 answers, with no new API calls.
  - P(YES) = P(YES) / (P(YES) + P(NO)), read from the answer token's logprobs;
  - the highest per-rule P(VIOLATION);
  - the share of runs that flag the article;
  - the number of rules named;
  - mixes of these.

### Evaluation

- **Metrics:** precision, recall, F1, **F2** (main score) and accuracy. A positive is an article flagged as a violation.
- **Why F2:** recall counts twice as much as precision. A reviewer can dismiss a false alarm, but a missed violation is never seen.
- **Same articles:** every approach is scored on the articles all of them ran on, and each number is the mean of 3 runs.
- **95% intervals:** bootstrap over articles, 1,000 resamples, stratified by class. Approaches whose intervals overlap are treated as tied.
- **Confidence-score thresholds:** chosen leave-one-out, so the threshold never sees the article it decides.
- **Rule level:** the share of named rules that are correct, and the share of correct rules that are named.
- **Highlight level:** character overlap between the highlighted words and the annotated words.

## Results

**English (62 articles), gpt-4.1, F2 as the mean of 3 runs**

| Task             | Zero-shot | Few-shot | Per-rule |
| ---------------- | --------- | -------- | -------- |
| YES/NO           | 65        | 84       | 58       |
| Rule detection   | 87        | **89**   | 60       |
| Highlights       | 85        | 84       | 76       |

**Sinhala (44 articles), F2**

| Task · prompt              | gpt-4.1 | Gemini 3.5 Flash | SinLlama 8B |
| -------------------------- | ------- | ---------------- | ----------- |
| YES/NO · zero-shot         | 58      | 0                | 22          |
| YES/NO · few-shot          | 72      | 24               | 36          |
| YES/NO · per-rule          | 58      | 16               | 49          |
| Rule detection · zero-shot | **86**  | 29               | 72*         |
| Rule detection · few-shot  | 83      | 36               | 43          |
| Rule detection · per-rule  | 64      | 23               | 49          |
| Highlights · zero-shot     | 84      | 35               | 24          |
| Highlights · few-shot      | 77      | 50               | 58          |
| Highlights · per-rule      | 70      | 23               | 49          |

\*SinLlama gets 72 only because it flagged every article.

Gemini ran out of credits (HTTP 402) and answered only part of the English set. `./run_missing.sh gemini` fills in the rest once credits are available.

**Sinhala code vs English code** (gpt-4.1, Sinhala articles): the average F2 over the 9 ways falls from **72 to 58** with the Sinhala code. It is worse in 8 of 9 ways and never better. Likely reasons:

- the Sinhala code needs about twice the tokens (7,535 vs 3,419);
- the model was trained mostly on English;
- the prompt mixes languages;
- meaning is lost in translation.

The code stays in English for every article.

**Top 4 per language** (gpt-4.1, ranked by F2 among all candidates)

| #   | English (62 articles)                         | F2 (95% CI) | Sinhala (44 articles)                       | F2 (95% CI) |
| --- | --------------------------------------------- | ----------- | ------------------------------------------- | ----------- |
| 1   | Share of all 27 runs that flag (≥ 8 of 27)    | 92 (82–99)  | Mix of the 27-run share and mean P(YES)     | 90 (77–97)  |
| 2   | Mean P(YES) of the 3 YES/NO prompts           | 91 (82–99)  | Rule detection zero-shot, all 3 runs flag   | 89 (76–97)  |
| 3   | YES/NO few-shot P(YES)                        | 91 (82–99)  | Share of all 27 runs that flag              | 88 (74–96)  |
| 4   | Rule detection few-shot, ≥ 2 of 3 runs flag   | 91 (81–98)  | Rule detection zero-shot, by rules named    | 88 (75–96)  |

Over both languages, the share of all 27 runs is #1: F2 90 (83–96), precision 86, recall 91, with 43 of 47 violations caught and 7 false alarms.

## Limitations and next steps

**Limitations**

- **Few violations:** only 47 (15 Sinhala), so the intervals are wide: 13–15 points overall and up to 30 in Sinhala.
- **Assumed clean articles:** the English ones were not reviewed.
- **Wrong rules:** detection works, but the named rule is correct only 67–74% of the time. Judgement rules (2.5, 6.1.a, 7.1) are often named wrongly, and 2.2.a causes most false alarms.
- **Sinhala false alarms:** precision is 70–78 even for the top approaches.
- **Optimistic ranking:** the top approaches were chosen on the same articles they are scored on.

**Next steps**

- **More data:** review more Sinhala violations and a set of English clean articles. Add Tamil.
- **Gemini:** finish its runs and test cheaper models.
- **Thresholds:** a stricter one for Sinhala.
- **More probability scores:** record token probabilities for the zero-shot and few-shot rule detection and highlight runs.
- **Classifier:** train BERT / XLM-R on LLM-labelled data.
- **Reviewer triage:** rank unreviewed articles by confidence score, and show the suggested rules and highlights.

## Database tables (`violations` schema)

| Table                    | Contents                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| `article_review_status`  | Snapshot of the source review statuses                                                        |
| `violation_articles`     | Violation articles (platform + confirmed external) with text; the runners read from here    |
| `non_violation_articles` | Clean articles; `--negatives N` takes the first N per language                                |
| `external_candidates`    | All external spreadsheet articles                                                             |
| `external_review`        | Decision per external article (all 28 confirmed); never truncated                            |
| `manual_annotations`     | Correct rules and highlights per article; never truncated                                    |
| `llm_predictions`        | YES/NO answers with P(YES) and per-rule details                                              |
| `rule_predictions`       | Named rules with evidence                                                                     |
| `span_predictions`       | Highlights with character offsets (also the two-step runs)                                   |

The prediction tables have one row per (article, experiment, model). A re-run overwrites that row.

## Adding a prompt

Create `<task>/prompts/<name>.py` with:

- `NAME`;
- `build(article) -> (system, user)`;
- `parse(text)`.

It may also define `EXCLUDE_IDS`, `JSON_OUTPUT`, `MAX_OUTPUT_TOKENS`, `parse_details(text)` or `token_confidence(tokens)`. Run it with `--prompt <name>`. To show it in the viewer, add it to `SHOWN_EXPERIMENTS` in `app.py`.
